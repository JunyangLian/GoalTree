# 长期目标、上下文与记忆的可靠性改进

本轮侧重既有链路的正确性和解释能力，不增加新面板、权限档位、任意Shell或通用插件安装器。

## 变更对验收的影响

`title`和`context_notes`是显示/背景元数据：只增加revision，不更换Task执行会话、不增加spec_version，也不让下游成果失效。确实改变范围、约束或验收时，应更新description、constraints或acceptance，而不是把范围变化藏在标题里。

`description`、`acceptance`、`constraints`、`parent_id`、`depends_on`或verification_mode变化会沿子任务及显式依赖传递失效，保留旧运行、产出和上下文历史。`plan_tasks`也遵守该规则，不再只修改当前未执行节点而漏掉已有下游草稿。一个方案内先解析全部别名、校验完整关系，再一次性失效，避免重复旋转上下文；环路或跨Goal关系使整个事务失败。已有产出的任务不能用plan_tasks覆盖。

前置任务归档、取消或转为未验收状态时，下游旧验收结论失效。任务绑定、实际启动、运行结束分别复核必要的当前状态；即使执行过程测试通过，前置依赖在运行期间失效，也不能把该结果登记成有效完成。

已有SQLite事务、版本冲突和宿主验收权限保持原样。这里只对显式结构关系作影响分析，不宣称理解所有语义依赖；未声明的依赖无法精确传播。全局目标规格/工作区文件变化继续采用原有保守失效策略，未实现精确到段落的成果依赖分析。

## 分层保留上下文

`GoalStore.context`派生`continuity`视图：当前Goal/Task及祖先的规格、约束、验收与背景备注，以及尚未完成的任务前沿、依赖问题、失效原因、恢复原因和历史证据引用。Task上下文只包括其本身、祖先及显式依赖；无关兄弟Task和其他Goal不因新视图泄露。

前沿最多30条，并明确省略数，当前Task优先。依赖未满足时不能将下游标为可执行；归档前置必须先明确恢复。可执行标记不是用户授权，重启后应核对未决副作用，不自动重放。规范状态仍由GoalStore和验证收据决定，备注与历史指针均不是权限或新的验收。

原生协议压缩仍按完整assistant/tool组处理。原始本轮请求、当前宿主状态和当前指令不截断；放不下时明确拒绝模型调用。可选历史摘要按纠正、修改、验证、失败线索和查询相关证据分类选择，不再固定只留最近8条；类型与词项相关性是机械策略，不声称已实现语义摘要。

最后预算压缩先省略较不相关的证据预览，再按相关性/类型省略历史条目。实际路径、命令和正文用于相关性，不把字段名`evidence_id`当成匹配依据。记录初选条数、最终送达指针、因预算省略的预览/条目及实际请求哈希；省略可选信息不等于其事实不存在。必要的当前约束始终在保护帧内。所有历史工具内容仍是不可信资料，不通过摘要升级为用户指令，也不存储内部Thinking正文。

## 统一排名，不静默上传记忆

自动学习的active条目先经过Goal/会话、状态、新鲜度、来源及路径授权过滤，再复用`RepositoryIndex.rank`的BM25机制。记忆和代码使用同一排名实现，但属于不同集合，不能因为检索得分高就跨Goal召回。

代码检索可显式配置既有真实Embedding；这不授权向Embedding服务发送新增私人记忆。自动学习记忆目前强制本地词项排名，审计标明dense_allowed=false；不把BM25包装成语义检索。跨措辞召回仍受限制，对明确“已有偏好”等指代保留原有范围内最近有效记忆兜底。

学习记忆正文和适用条件一起进入上下文，不再分别截断。单次active建议正文总预算4200字符，超出则整个条目省略并记录ID，不发送半条失去条件的建议。候选Skill试用、长期知识和旧会话笔记仍保留各自范围和治理路径，没有假称完全统一了所有记忆系统。

## 检索效率

仓库仍逐次读取并校验允许文件的内容哈希；哈希相同则复用已有AST/切块结果，删除文件、同尺寸修改、恢复mtime、权限撤销均不能沿用旧内容。BM25每批只计算一次文档词频统计，避免为每条查询词重复扫描所有文档。

这是内容验证后复用解析结果，不是文件监控服务或持久化增量索引。已有200文件/800片段/约2MB源码等小规模限制保持不变；未测大型仓库性能，不宣称固定加速比例。

## 调用顺序与剩余边界

未绑定Goal的统一对话若先调用plan_tasks，在工具参数校验阶段就拒绝，要求先create_goal；不会先询问用户确认一个注定失败的方案。合法的规划方向、工具写入、Shell和最终验收仍走原审批。

通用文档的事实准确性和语义质量仍需人工验收；AppContainer执行范围仍受现有精确命令限制。没有为了扩展通用能力放宽权限。当前证据不支持“达到主流产品稳定性”“自进化显著提高泛化”或“向量召回已经改善”的结论。
