# 长任务与同对话目标切换：试验协议 v1

本轮先运行两个自设计开发场景各一次：12轮研究规划＋7轮三目标切换。共2条序列、19个用户轮次，检查点不是独立任务。不做产品排名，不把历史代码修复成绩移到通用目标能力上。

## 冻结与隔离

`benchmarks/goal_stress_v1/`存放协议、任务、外部金标和13份公开合成资料（总计60,920 UTF-8字节）。首次请求前冻结这些资产及Harness、运行器、外验器和测试的SHA256。仅`public/`复制到全新工作区；金标、外验代码和参考输出不进入Agent工作区。用户正常给出的事实与所读资料属于任务输入，不属于答案泄漏。

复用当前Workbench、GoalStore、真实原生Tool Calling、检索、学习、隐私与审计。由Host预建明确的目标/任务夹具，故不评估从零生成任务树的能力。Agent仍需自己调用读取、更新上下文及提交草稿等工具。没有脚本替它填答案、改状态或选择目标。

## 实验A：研究规划与压缩压力

经历初始约定、文件核读、基线检查、三批资料、需求纠正、旁支解释、后期检查、草稿交付和服务对象重建后的同会话检查。

四个检查点分别判定8项字段：物种、预算、样本数、项目代号、文件登记号、分析顺序、表达偏好、验收状态。旧物种/预算/样本必须被新要求替代；未验收不能说已完成。登记号与顺序来自早期工具读取，和始终保留的用户约定分开观察。最终交付另检查内容、旧值误用及真实草稿证据是否关联到已有任务的待验收状态。

输入限制固定60,000序列化JSON字节，context ceiling为98,304字节。这是**较小固定预算下的长任务压力试验**，不是自然1M Token窗口填满。至少10个不同文件成功读取且至少2次真实请求发生压缩，才满足压力资格；达不到则明确标为压力未触发，不能宣称通过超长上下文验收。服务对象重建只验证同一持久会话恢复，不算跨会话永久记忆迁移。

当前Harness保留历史用户要求，不能把这些字段答对当作压缩后记忆收益。额外记录工具独有证据是否进入取得实际用量的模型请求；prepared候选请求与成功取得响应分别标记。

## 实验B：同一对话切换三类目标

目标为研究方案A、会议报告B、解析器修复C；固定原A会话，用户自然语言请求B→A→C→B→A→C。对话理解、回复中声明的Goal ID、实际运行绑定、错误目标修改、其他目标状态分别判定。

已知当前Host禁止Agent自行切换Goal。这是本试验要如实暴露的产品边界，不由控制器代为路由、不移除安全规则、不另开会话伪装成功。安全地说明无法切换，属于路由能力未完成，不能归为越权成功或隐私攻击。

目标内容全为公开合成数据；串线是任务上下文/状态错误，不据此声称发现真实用户隐私泄漏。所有显式要求的目标都应被正确定位；含糊指代不在v1中评估。

## 独立判定与预算

外验器`scripts/verify_goal_stress.py`不导入Harness、不调用模型，只消费冻结金标、真实回答、树状态及请求观察记录。数值要求JSON整数；文本采用运行前冻结的候选值或必要概念正则。措辞/格式不符合需单列，不能据此直接断言记忆丢失。最终交付使用固定内容约束和真实产出记录双重验收。

记录检查点和字段分母、真实绑定、同会话ID、压缩前后字节、证据可见性、重复读取、工具失败/步数、Token和时长。重复读取可能是合理恢复，不自动算低效。不能可靠观察的语义指标不补零。

使用GLM普通API `glm-5.3-flash`、temperature=1、top_p=.95、Thinking enabled / low、输出2048 Token、超时90秒、传输1次、并发1、每轮最多8工具步。v1上限400,000 Token、按既有2026-11-06费率快照估算1元、70次请求任一先到停止；每次请求前预留，未知用量停止后续派发。v1已因截止取消和未知用量停止，没有继续该批次。修复后的v2在首次请求前另行冻结，总Token上限调整为600,000，估算金额上限仍为1元；使用`--carry-budget`原样继承v1的全部用量与未知预留，不能归零或从分母删除。任务、金标、资料、模型参数、60,000字节输入预算及300秒单轮截止均不变。两个批次分别报告，不合并为一次干净成功实验。估算不是当前价格保证或真实账单。仅使用本地凭据。

原ask策略与AppContainer配置不变。控制器只按冻结范围批准当前夹具内的规划/进度变更，不允许Shell、委派、联网、跨Goal写入或代替人验收。观察器不改变模型输入和压缩算法；保护模式不启用原始wire回调，不保存Thinking正文，只保留请求哈希及去除Thinking的模型可见消息。

## 复现与后续

```powershell
python -X utf8 -m pytest -q tests/test_goal_stress_pilot.py
python -X utf8 scripts/eval_goal_stress.py --output artifacts/my-goal-stress-offline
python -X utf8 scripts/eval_goal_stress.py --output artifacts/my-goal-stress-live --live
python -X utf8 scripts/verify_goal_stress.py --output artifacts/my-goal-stress-live
# 修复后另冻批次时继承原账本，不恢复、覆盖或替换旧失败：
python -X utf8 scripts/eval_goal_stress.py --output artifacts/my-goal-stress-retest --live --carry-budget artifacts/my-goal-stress-live
```

输出目录必须是新目录。每个批次保留freeze、slots、预算账本、原始输入/结果、去除Thinking的请求观察、响应元数据、审批、工作区轨迹、逐轮CSV和独立报告。v1中断和失败不删除；修复需另冻版本再测。后续科研/文档/代码三个场景的重复实验须独立预先登记，不根据本批成功与否筛选计分样本。
