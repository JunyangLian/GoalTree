# 公开 PDF 读取

当前GLM网页入口仍使用Exa Search MCP搜资料，实际PDF由原受控公开网络通道下载并在本地提取文字，不把整份文件发给Exa。已有网页、缓存、来源和工具审批规则保留，没有额外按钮或第三方阅读Key。

## 使用

直接对话：“读取这个PDF，回答会议日期、地点、主办与承办单位，并附页码来源。”也可以提供官网页面，让Agent沿`embedded_content.document_urls`发现日程PDF。支持已观察到的iframe和脚本中字面PDF引用，不运行网页JS；可识别PDF.js路径`.../pdfjs/.../viewer.html?file=...`，仅做安全URL解析，保留原HTTPS降级拒绝与DNS检查。

`web_read(url=...)`会按application/pdf类型及%PDF-签名识别PDF；`page_id`仍为当前会话独立wp_快照。默认`start/limit`读取全局快照行；`pdf_page=2`在start=1时定位第二个物理页，返回该页最多limit行。之后省略pdf_page，用返回的全局next_start继续。GLM网页入口现允许limit为1..120，默认仍为10；普通Workbench保留1..20默认策略，以工具说明及`/api/config`为准。`web_find(page_id,pattern)`能定位字面词，返回物理页码、全局行和引用；不会把跨两个PDF物理页的拼接文本误判为同一连续命中。

GLM入口每轮网页工具累计输出上限120,000字符，单次12,000字符（包含JSON元数据），按实际装得下的行裁剪并返回next_start。全部网页工具共用配额，子任务共用父任务配额，切换工具不能重置。网络次数和解析权限不随之增加。详见[上下文与文档预算](context-budgets.md)。

每条PDF结果行有`page`；引用形如`wp_...:P1-P1:L6-L12`，网页回复应引用真实源PDF的`#page=1`。页码是文件物理顺序，从1开始，不等同于印刷页码。行号是清洗/折行后快照位置，不是PDF排版坐标。输出裁剪后页码与行号会同步更新。表格列关系、图像和公式版式不做结构还原，不应根据纯文字拼接补造关联。

## 边界与依赖

- 可选依赖：`python -m pip install -e ".[web-pdf]"`，使用pypdf>=6.21.1；缺依赖时明确报安装提示。本机使用6.21.1，没有为此新增外部模型调用。
- 单PDF最多5MiB、40页、60,000提取字符；超限和加密文档拒绝，不接受或猜测用户密码、不默默截断后宣称全文已读。
- 网络文本仍限512KiB；只新增标准application/pdf二进制类型，非PDF MIME/签名、普通任意文件仍拒绝。
- 原2次搜索/3次新资源/8次网络尝试/20秒累计阶段时间不变。一个PDF只获取一次，局部复读/查找不联网；解析时间计入该次原8秒阶段时限，解析自身最多5秒（含进程启动）。不保证DNS或系统阻塞的硬实时截止。
- 解析器用固定可信Python文件与stdin原字节，`-I -B`，不使用Shell，不传API Key、代理或工作区环境，不按PDF内容打开文件/网络。Windows Job或POSIX资源限制设置512MiB进程内存，Windows限制一个活动进程；pypdf解压流、总内容流也有上限。超时/取消杀掉解析进程。
- 该资源受限解析进程**不是AppContainer文件系统/网络沙箱**。它运行固定的本地解析程序，不执行PDF JS、动作或附件；原Agent Shell的AppContainer、ACL、审批和验收策略未变。不声称PDF解析库没有漏洞。

## 完整性、缓存与审计

提取所有允许页的文字层，再按需给模型片段。每页无可提取文字时，生成明确的“可能需要OCR、尚未识别”占位；状态为needs_ocr或partial_text，工具轨迹为partial_success，不把占位当作PDF原文查找命中。文字页状态text_extracted也不表示已视觉阅读图片、核验表格或将所有行提供给模型。尚未实现自动OCR。

文字快照、页码映射、原文件SHA256、提取文本SHA256、获取时间及解析器版本写入现有EvidenceStore，原文件不作为产品缓存长期保存（验收原件单独保留在validation中）。会话与工作区隔离、15分钟缓存、refresh新版本和旧ID快照规则保持；快照抽取格式版本3与旧HTML抽取缓存区分。已知凭据（包括URL解码后的值）在实际发请求前检测。网页/PDF均标注为不可信证据，内容不能改变权限或授权命令。

真实验收、源文件哈希、截图、测试和命令见[发布检查](releases/goaltree-2026-11-10.md)。该功能验收不计入旧代码修复Benchmark。
