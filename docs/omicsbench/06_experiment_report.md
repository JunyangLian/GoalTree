# 06 · bovine 四组消融实验报告（最终版，含两轮 k=3）

> 边界：本地开发评测，真实模型（GLM 5.3-flash）+ 真实数据 + Windows HostEnvironment（无 Docker），**非官方 OmicsBench 成绩**；评分用独立开发判分，非官方 grader。
>
> 已修复消融开关缺陷：`ScientificStages` 三档独立，A/B/C/D 真实可分；每组 k=3 重复。
> 本报告综合**两轮** k=3 实验：`exp2`（120s 墙钟，无环境提示）与 `exp3`（200s 墙钟，含「优先用 Python」环境提示）。

## 1. 两组任务均分对比（核心）

| 组 | exp2 任务均分 | exp3 任务均分 |
| --- | --- | --- |
| A（基线） | 0.222 | 0.444 |
| B（约束） | 0.667 | 0.556 |
| C（约束+验证） | 0.667 | 0.444 |
| D（约束+验证+纠偏） | **0.333** | **0.667** |

**关键观察：两组排名完全反转。** exp2 里 D 最差、B/C 最好；exp3 里 D 最好、B/C 居中。这在统计上直接证明：**k=3 下四组差异是噪声，没有任何一组可复现地更优。**

## 2. 每节点均分（两轮）

| 组 | node1（exp2→exp3） | node2 | node3 |
| --- | --- | --- | --- |
| A | 0.0 → 0.0 | 0.333 → 0.667 | 0.333 → 0.667 |
| B | 0.0 → 0.0 | 1.0 → 0.667 | 1.0 → 1.0 |
| C | 0.333 → 0.0 | 1.0 → 0.333 | 0.667 → 1.0 |

## 3. node1 是唯一稳定的瓶颈

- 两轮合计 node1 共 **24 次**运行，正确仅 **1 次**（exp3 D·run0），其余为超时或「valid 但答案错」。
- **200s 墙钟 + Python 环境提示都没有真正改善 node1**（exp3 的 node1 仍 A/B/C=0.0、D=0.333）。
- node1（差异表达 + grouped JSON 输出 + 需精确 log2/fold-change 分组）是当前模型/执行环境无法稳定完成的高难度节点；它与「方法漂移」无关，是「算不对/跑不完」。

## 4. 验证器行为（两轮合计）

| 状态 | 含义 |
| --- | --- |
| C001 方法漂移 VIOLATION | exp2 检出 2 次；exp3 检出 0 次（本轮模型未用校正 p，不等于不存在漂移） |
| answer_provenance VIOLATION | 两轮多次，均对应「无答案/超时」，判断正确 |
| UNVERIFIED | 大量（p 阈值、direction、scope 缺结果表/样本清单证据） |
| 误报（正确却判错） | **0** |

验证器实现正确、无误报；但它抓的是「漂移/无答案」，而 node1 的失败是「算不对/超时」，所以**验证器对任务正确率没有贡献**。

## 5. 结果三分类

- **实际运行结果**：§1/§2 的均分、墙钟、验证状态，来自两轮 k=3 真实运行（`exp2`/`exp3/report.json`）。
- **自动化测试结果**：`pytest tests/test_omicsbench_adapter.py tests/test_omicsbench_scientific.py` → **35 passed**（分档、防泄露、早退、恢复、V1 漂移判定的确定性实现）。
- **未验证/不支持**：增强机制可提升正确率（两轮数据**不支持**）；纠偏能修复漂移（无证据）；结论可外推（未验证）。

## 6. 结论（诚实、决定性）

1. **在 bovin 这个公开任务上，A/B/C/D 四组在 k=3 × 两轮实验里没有可复现的正确率差异**（排名反转 = 噪声）。
2. **瓶颈是 node1 本身**（高难度 + 超时 + 算错），与科学约束管线的目标（方法漂移/持久化）无关，因此约束/验证/纠偏**无法**提升它。
3. 环境提示与墙钟调整**未**解决 node1——需要在更根本层面（更长的预算、更稳定的执行、或更强/不同模型）处理，而非继续在科学管线上叠加。
4. 本结果**不支持**「科学约束 + 证据校验能减少执行偏离并提高正确率」这一原假设（至少在成活 lib、当前模型、当前节点难度下）。

## 7. 建议下一步

- 停用对 A/B/C/D 的继续盲目增补；先定位并修复 node1 的「跑不完/算错」根因（预算、命令可执行性、模型选择）。
- 若要继续验证增强机制，需换/降低节点难度，或换更强模型，并把 k 提到 ≥5~10 才有统计意义。
- 全部结论仍限定为本地开发，非官方成绩；缺 token 指标、缺大样本，下结论须谨慎。
