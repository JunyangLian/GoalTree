# 对话驱动的动态任务树与阶段验收

任务树继续由Agent维护，右侧保留只读查看；统一对话负责提出需求、调整范围、提交产出与推进阶段。

## 进度不等于验收

|状态|含义|依据|
|---|---|---|
|待进行|当前要求下尚未提交工作|已保存的任务规格|
|进行中|已启动对话工作或独立任务运行|显式进度记录或run_task|
|待验收|已提交可查看的产出，未确认合格|当前会话产出证据或实际运行结果|
|已完成|按当前要求通过验收|配置验证器通过，或审批后的人工验收|
|待复核|历史完成结论因规格/文件变化而失效|版本与工作区有效性检查|

进入“阶段3”的聊天本身不会证明前两阶段已验收。普通对话产生的大纲/草稿现在可通过`goal_action record_progress`关联到原任务，无需为了更新进度重复调用子Agent或Shell。状态只允许active/review，不能用该动作自行标记完成；review必须附实际output或当前会话有权读取的产出evidence_id，不能将搜索片段当成已交付内容。

新产出单独保存到EvidenceStore，任务保留证据ID、内容哈希、关联运行与任务规格版本。若模型最终只说“已交付”，宿主会把本轮实际提交的新产出补入对话，避免工具参数成为用户看不到的文档。严格原文判断也可能使改写后的最终回复包含重复内容，这是当前保底显示策略的局限。

父阶段继续汇总子任务，但不自行批准它们。`confirm_task(include_children=1)`可用一次审批验收一个阶段及其已提交的子树：

- 确认框使用宿主读取的真实标题、验收条件、版本、进展与产出预览，不采用模型捏造的节点清单。
- 未提交产出的叶子不能批量验收；已归档/取消节点不纳入当前范围，运行中/失败/阻塞的节点不能验收。
- 用户拒绝则维持待验收；允许后按子节点到父节点顺序在同一个SQLite事务提交。
- 确认期间范围或版本变化则整批拒绝，不产生部分通过。保留原审批、权限、工作区及会话边界。

## 后续对话改变计划

Agent每轮获得当前目标内节点、版本和已有产出引用。成功修改后，后续原生模型请求携带最新goal_tree状态，优先于首次请求中的旧快照；不会重放全部旧工具文本。最近3份已正常完成的对话产出以有会话权限的证据指针携带，不能当作源事实验证。

更新已有节点用`update_task`；新增用`create_task/plan_tasks`；取消范围用显式归档，不删除历史。已经执行或有产出的任务不能用plan_tasks覆盖，需显式改规格并保留旧上下文/运行/产物。需求改变后，旧review稿回到待进行，旧证据保留；不能直接批准为新规格的产出。

新增背景信息写入目标context_notes，改显示名称或备注不再使全部子任务失效。目标description/constraints/acceptance仍属于规格变更，会保守失效相关任务；这不是语义级精确影响分析，因此应避免每轮重写目标说明。

父节点的规格修改可能刷新子节点版本。冲突会拒绝原修改、返回当前节点，并要求Agent在剩余预算内修复；不能静默替换revision。存在这类未解决更新时，正常最终完成会被拦截，工具/尝试预算耗尽则明确停止，不让用户靠刷新修补Agent自己的版本错误。

## 历史数据

现有历史任务不会被批量伪造为完成。旧工作区可能曾因补充目标说明被保守失效；新对话可核对近期实际产出后关联为待验收，再由一次阶段审批确认。未完成、断流或已停止运行的半截草稿不会被当作已正常完成的历史交付。
