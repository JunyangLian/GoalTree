# SSE完整性、诊断与恢复

GLM网页入口保持原生Chat Completions工具协议、流式正文和工具参数。服务端正常返回时，仍须同时收到非空`finish_reason`和`data: [DONE]`才可提交本次助手响应；工具名称、参数与权限继续走原校验。不能因为参数看起来像完整JSON，就执行没有完整结束的流。

## 中断如何处理

`IncompleteSSEError`区分正常读到EOF但缺少结束信号、读操作异常与读取超时。它记录已接收字节数、数据事件数、正文/推理/工具参数字符数、结束信号、usage是否收到、耗时与原始已接收SSE字节SHA256。诊断中没有推理正文或工具参数文本；原始私有推理不会因此新增落盘。

GLM网页入口最多2次传输尝试，即初次请求加最多1次自动重试；和可重试的HTTP/网络错误共用次数，而不是层层叠加。依然有原`timeout*2`总重试软预算及每次Socket超时；在每次流读取前还检查本次请求剩余总时长，防止持续零星返回绕开Socket空闲超时。已阻塞的单次读取仍受Socket超时约束，这不是硬实时上限。取消会中止等待与后续重试。鉴权、权限、超大响应、非法工具协议等问题不会因此获得无限重试或执行权限。

后续补充了`read_wait_ms`、`consumer_callback_ms`与`max_read_wait_ms`，分别观测读取等待、本地进度/正文回调耗时和最大单次读取等待。读取等待也受网络缓冲影响，不能直接等同于模型推理时间；回调耗时可能包含日志、状态保存与锁等待。详情见[长回复吞吐修复](releases/goaltree-2026-11-10.md)。

重试的是当前模型请求，保留之前已确认的工具结果。残缺响应不进入`NativeToolConversation.accept`，不产生待执行工具，不重放已经完成的写入。不会静默切换到非流式、DSML、其他服务或其他模型。记录每次实际尝试的请求ID、阶段、是否重试及流诊断。

浏览器收到`model_transport.stream_reset=true`时，仅清除本轮未完成的正文预览，再显示重试响应；历史事件和失败证据保留。子任务事件不会清空父对话。最终仍失败则显示“模型回复流中断”，保留原会话和已完成操作，错误记录不冒充最终成功。

## Token和效果边界

流中断时可能没有完整usage；失败尝试计入`unknown_usage_attempts`，不能按0计算。即使第二次成功，也只汇总已知Token，并标记整个运行成本统计不完整。

客户端恢复不能证明服务商、网关或网络不再断流。历史日志缺少结束信号快照时，也不能追认一定是某个网关的120秒上限。新诊断用于下一次区分这些情况。不得把较短、不同提示的成功验收解释为故障率下降的因果证据。
