# 附件与双轴协作方式

2026-11-08。输入框左下角的“＋”用于添加文件或图片，右侧按钮分别设置项目规划、项目实现的协作方式。默认两项均为适中，设置绑定当前对话，切换Goal后独立恢复。正在运行时不能更改；每次运行保存一份设置快照。

## 三档行为

| 维度 | 逐步确认 | 适中 | 自主 |
|---|---|---|---|
| 项目规划 | 创建/修改目标与任务需要确认；批量规划每个任务逐项确认，全部同意后原子保存 | 目标范围、顶层阶段变化、归档和阻塞等需要确认；阶段内常规细节由Agent处理 | 在当前目标内自主拆解和维护规划，保留原范围限制 |
| 项目实现 | 启动任务以及读取等具体步骤需要确认；风险操作使用原安全审批 | 确认每个Task的启动，之后常规读取由Agent完成；风险操作使用原安全审批 | 减少任务启动和只读步骤的协作确认；风险操作仍使用原安全审批 |

这两项是协作自主程度，不是OS或工具授权。选择自主不会自动开启 `policy=auto`，也不会放宽路径、敏感文件、Shell、AppContainer、策略钩子与人工验收。仅要求规划不等于授权实现。网页默认安全策略始终是ask；带协作设置的请求即使传入auto也会收紧到ask，never不会被放宽。

规划和实现设置会进入模型上下文，但关键检查点也由宿主强制执行。拒绝时工具不生效，取消会中止等待；服务重启后旧审批失效，不自动重放。模型不能使用Goal工具改变协作设置。适中模式的主方向判断依据顶层任务结构与目标规格；它不是已经验证的语义意图分类器，细节中的关键选择仍需模型根据规则询问。

## 附件

- 每条消息最多4个附件，单文件最多5MB。支持UTF-8文本、代码、CSV等，以及PDF、DOCX、PNG/JPEG/WebP。
- 文本及提取出的文档文字最多60000字；PDF最多40页，不支持加密或无文字的扫描PDF。扫描内容可转成图片上传。
- PDF和DOCX当前只提取正文文字，不自动读取嵌入图片，也不保持原排版或执行OCR；需要模型看图时请单独附图。
- PDF和图片解析使用可选依赖：`python -m pip install ".[attachments]"`。缺少依赖时会明确报错，不把未解析文件当作已读。
- 图片解码校验后去除元数据，合成白色背景，最大768×768并重新编码为JPEG。适合截图、流程图等参考；精细数字、微小文字与科学图像应提供原始文本或表格，不能把压缩预览当作精密测量依据。
- 当前仅为已验证的GLM原生多模态配置开放图片输入。其他模型会拒绝图片，避免只传文件名却声称读图。
- 附件作为不可信任务资料进入当前Goal上下文，图片通过实际 `image_url` 数据输入传给GLM。不会将附件自动写成项目文件，也不从附件提取权限。
- 上传绑定会话ID；新对话或其他Goal不能引用其附件ID。当前对话后续消息可以继续使用最近一次附件集，显式分派的Task可以使用此次传入的资料。跨Goal不自动迁移。
- 发送前可预览图片并从待发送区移除。移除待发送项不删除已上传的私有审计资料，也不撤回历史已发送消息；刷新保留已发送附件的元数据，未发送的草稿当前只保留在浏览器内存中。
- 内容保存在工作区 `.pico/conversation-assets.sqlite3` 中，Git默认忽略；工作区附件总量限制64MB/100个，不自动删除旧资料。图片预览只提供规范化后的图片字节，原始文档不作为可执行网页提供。
- 实际模型请求仍受既有上下文预算限制。多个较大的文档或图片可能超过预算并明确失败，不会静默剪掉目标约束或伪称已完整读取。

## 验证边界

宿主策略、权限拒绝和附件隔离通过自动化测试验证；Tabbit完成真实选择文件、图片预览、移除重传、设置切换与刷新验证。另有一次真实GLM图文读取：准确返回文本项目代号与流程图三个阶段，0工具步。这是小规模集成验收，不是跨领域识图或自主执行能力的Benchmark。
