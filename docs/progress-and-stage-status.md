# 对话进度、确认预览与阶段状态

2026-11-08。

## 对话进度

对话内显示可折叠的执行摘要，而不是长期停留在“正在处理”。状态来自实际请求与工具事件：等待响应、连接模型、模型分析活动、生成正文、准备操作、等待确认、工具返回及失败/拒绝。耗时标为**总耗时**，不是单次模型请求时间，也不代表进度百分比。

GLM网页入口启用 `stream=true`、`tool_stream=true`。正文逐步显示；分析阶段只发出节流的状态事件，不发送内部推理原文，不根据未完成参数执行工具。原生工具调用必须完整组装并通过校验、协作确认与原安全审批，才能执行。Thinking与原始tool_call ID在内部按原协议回传，执行摘要不复制这些内部内容。

运行结束后摘要默认折叠。刷新可恢复与该条回答匹配的真实摘要；旧记录按精确的用户请求与最终回答匹配，无法确认归属时不猜测。失败不被改写成成功，“本轮回复结束”不等于目标完成或验收通过。

## 确认框

先展示可读的标题、说明、边界与验收条件，支持Markdown标题、加粗和列表；原始参数放在可折叠区域。写入Markdown文件时预览实际正文，源码、命令与补丁保留字面格式。大于12000字符的内容会明确标记预览截断，完整参数仍可展开核对。

沿用本地安全Markdown渲染器：不执行HTML、不加载输出中的远程图片、不允许脚本链接。显示优化不影响允许/拒绝结果或工具权限。

## 父阶段状态

父阶段具有自己的验收状态，同时拥有从子任务派生的进度。API保留原始 `status`，增加 `display_status` 和 `rollup`；UI使用派生进度，模型上下文同时明确两者含义。读取不修改数据库、规格版本、会话或历史审计。

- 所有子任务未开始：待进行。
- 部分子任务进行、完成或待验收，另有未开始项：进行中。
- 子任务均完成或待验收：父阶段待验收，不能因文本回复或进度比例自动通过。
- 子任务有阻塞或失败且没有正在执行项：父阶段显示阻塞。
- 子任务都有效验收，且父阶段自身也已验收：完成。
- 子任务重新打开或证据失效：重新汇总，父阶段不再显示完成；依赖该父阶段的执行也会被拦截。
- 归档或取消的子任务列为排除项，不当成已验收。空集合不会自动完成阶段。

例如“阶段1：需求界定与技术选型”有1项待验收、2项待进行时，显示**进行中 · 0/3**，详情列出待验收数量。0/3表示有效验收数量，不是已经产出文档的数量。
