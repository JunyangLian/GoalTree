# 跨对话背景的只读来源核对

共享记忆“被检索并送入模型”不等于“被正确用来回答问题”。长流程曾出现模型把当前Goal代号当作共享资料代号，错误答案又进入后续历史。本次在不改变共享授权、工具权限与任务验收的前提下，为部分背景问答增加一次独立读取。

## 引用与验证分开

Goal背景笔记仍标记为未核验。询问“笔记写了什么”时可以引用其说法；将说法用于重要决策或实际行动前仍需核验原始来源。来源Goal的事实不能被当前Goal的身份值替换，也不会变成当前Goal的约束、权限或验收。

宿主生成的Goal笔记适用说明作上述澄清；用户记忆条目自身的适用条件不被截断或改写。敏感/核心过滤、来源新鲜度、双方同意、同Workspace边界、撤销和CAS保持原有机制。

## 一次独立读取

目前适用于声明支持该能力的原生Chat Completions客户端，真实验收使用智谱普通API GLM-5.3-Flash。仅在本轮确实有共享参考、没有执行工具、候选回答不超过12,000字符时触发，每个Run最多一次。没有共享参考或执行过工具的轮次继续沿用原流程，不能声称这些轮次也获得了该核对。

1. 主Agent先产生候选答案。满足核对条件时，候选正文暂不流入网页；界面显示“正在核对记忆来源”。
2. 独立读取窗口仅接收当前问题和已授权条目的正文、来源与条件，不接收主Agent的错误答案或当前Goal身份值，减少错误值的锚定。使用同一配置模型、输出上限、超时与预算，不静默换模型。
3. 请求不提供tools或tool_choice，不执行任何动作。返回协议为decision、answer、citations；内部包不会作为最终聊天消息展示。
4. 宿主校验引文是否逐字属于实际检索条目，结构化值是否出现在引文中；显式`key=value`还核对字段与值的对应关系，拒绝借用其他字段值、标识符前缀和伪造来源。
5. 若主答案已有单字段JSON契约、读取器返回被引文支持的标量，宿主只按该既有字段包装格式，不替换成硬编码答案。多字段必须保持字段集合；事实值仍来自读取器与原文，不访问评测金标。
6. 采用前再次检查授权、宿主策略、来源版本及取消状态。通过后保存同Session核对证据及来源版本，只把最终答案写入对话历史。

读取器明确不足时记录`insufficient`并保留原候选，不将它标为核对通过。这可以避免不相关笔记覆盖用户更正或当前工具结果，但也意味着本机制不是所有答案的强制事实证明。伪造引文、协议破损或返回工具调用会停止采用，不能把不合法的核对结果当作成功；超时保留失败与用量不确定性，不追加新的核对轮次。传输层仍沿用宿主既有的有限重试配置（当前网页启动器最多2次尝试），本次正式实验固定1次尝试。

## 成本、审计与限制

主模型调用和独立读取分别记录model_requested/model_parsed、usage、耗时和attempts；核对不增加tool_steps。来源回执使用`shared_reference_grounding`证据对象，包含引文、来源版本和答案摘要，不记录思维正文。主候选和核对包均不提前展示；已产生的旧历史答案不会被追溯删除。

该检查证明的是引用确实来自已授权笔记，不证明笔记客观真实。一般自然语言转述、复杂条件冲突与来源适用性不能由子串/字段关联完全判定；没有词条可用也不等于外部世界不存在信息。仍需独立功能验收、安全验证与更广泛任务测试。当前配置多一次模型请求，不能把成功率变化全部解释为单个提示词的效果。
