# 搜索策略参考与GoalTree改进建议

核查日期：2026-11-09。本文的“当前能力”记录改造前状态；轻量实现已推进，参见[实现验收](releases/goaltree-2026-11-10.md)。本文件为官方资料核查与设计建议，不表示下列能力已在GoalTree实现，也不把API能力直接归为桌面产品的内部实现。

## 已公开的行为

| 对象 | 可确认的行为 | 官方来源 |
|---|---|---|
| 本地Codex | 区分缓存索引与实时搜索，搜索与本地命令网络权限分开；完整权限下的默认行为另有差异 | [Web search](https://learn.chatgpt.com/docs/web-search) |
| OpenAI搜索API | 模型可选择是否搜索；支持search、open_page、find_in_page，域名过滤、来源及引用信息 | [Web search guide](https://developers.openai.com/api/docs/guides/tools-web-search) |
| Claude Code | WebSearch发现标题和URL，WebFetch读取页面并按提取提示加工；读取结果有缓存 | [Tools reference](https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior) |
| Claude搜索API | 可反复搜索；支持动态过滤，使相关结果再进入上下文，并可限制搜索次数 | [Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool) |

不能从这些文档断言Codex在每次请求中并行哪些商业搜索引擎、采用哪一种融合排序公式，或按某个固定数量读取网页。Claude API的动态过滤也不能直接说成Claude Code默认使用的完整实现。当前可借鉴的是公开的工具分工、检索循环、上下文控制及来源记录。

Codex的缓存模式使用OpenAI维护的索引。拟议中的GoalTree本地TTL缓存是不同机制，只能借鉴结果复用和时效控制思路，不能宣称复现同样的搜索索引。

## GoalTree当前实际能力

- 工具循环允许模型再次调用搜索，已有Bing/360与Crossref/PubMed、多源去重、错误记录和预算边界。
- `auto`固定并行Bing与360，`research`固定并行Crossref与PubMed。模型能选择分组或单源，但没有专门的检索证据缺口/停止规则。
- `pico/web_tools.py`中`web_read`只给出约2600字符的正文开头。现有工具未提供页内定位、后续范围或页面快照ID；审计保存的提取摘录也不包含未返回的完整正文。因此回答在后半页时，继续读同一URL不能解决定位问题。
- 已保留URL、读取时间、响应哈希及工具证据。回答中的URL可以核对，但尚未建立“每条论断对应页面具体片段”的引用约束。
- 尚无网页结果的TTL缓存与显式强制刷新语义。已有文件/会话记忆不等同于网页缓存。

## 推荐实现顺序

### P0：可继续读取的证据页面

一次受限网络读取后，在当前工作区/会话中保存清洗后的有界页面快照，返回`page_id`、标题、来源、读取时间、版本哈希及局部正文。增加页内查找和按范围继续读取，避免机械扩大全文入模上限。保留既有512KiB传输上限、网络边界及只读权限，不执行网页脚本或页面要求的命令。

缓存与读取授权分开：保存内容不产生新的URL访问权、跨工作区共享权或执行权限。断网后的历史内容标注为历史快照；权限收紧时仍需重新检查访问范围。

### P0：将检索纳入Task的证据闭环

由模型提出待确认问题、适当来源和下一次查询，宿主限定调用/页面/总输出预算。每轮根据具体缺口选择下一步：回答、改写查询、阅读原文、定位片段、检查冲突或说明资料不足。不要新增一个关键词分类器来代替目标理解，也不要求用户在界面手动选检索模式。

普通问题先采用合适的单源查询；需要覆盖或交叉验证时再并行。保留用户明确指定来源的优先级和现有多源工具，不把所有问题强制变成四源搜索。域名优先级应根据主题选取，并明确区分偏好与必须执行的域名限制。

终止条件至少覆盖：必要问题已有足够证据；到达预算；用户条件不够明确；来源不可用；新一轮没有取得新证据。缺少资料不等于可以用模型知识补造来源。

### P1：证据引用与缓存时效

引用保存`page_id + 片段范围 + URL + 读取时间`。区分“检索命中”“读取正文”“某片段支持某论断”；跨来源重复转载不能直接算作独立证据。任务树只保留与当前Task相关的证据指针和结论，原始网页内容仍按授权会话读取。

增加按工作区隔离的有界TTL缓存、命中标记与强制刷新；稳定文档可复用，要求最新的信息重新获取。缓存命中不意味着内容仍最新，缓存失效也不自动删除历史证据。网页哈希是版本标记，不是事实正确性证明。

网页内容进入模型前优先按当前问题定位段落，保留标题/结构和必要上下文。摘要属于有损加工，不能把“摘要没有提到”当作“原文不存在”；需要时可回看快照原片段。网页事实未经用户确认与时效校验，不自动晋升为永久记忆。

## 小规模验收建议

固定少量场景即可验证机制：答案只在后半页、重复页面读取、旧缓存与最新页面冲突、官方文档与转载冲突、部分来源失效、预算耗尽、恶意页面指令、切换工作区后的页面ID隔离。预先冻结必要证据片段与验收条件，记录命中/漏读、引用是否支持论断、重复获取、缓存时效、上下文字符或可观测Token、延迟与停止原因。

这些是后续验收设计，当前没有实验数据，不能据此报告效果提升。检索是GoalTree目标推进的能力模块，不改变项目以Goal/Task和独立上下文为主的定位。
