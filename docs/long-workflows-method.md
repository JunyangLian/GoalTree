# 长流程批量诊断方法

这套检查服务于 GoalTree 的开发回归，包含多轮真实模型工作流、可控的宿主压力序列和全量自动化测试。它不是公开 Benchmark，不能把聊天轮数、同模板的主题变体或工具循环次数当作独立任务数量。

## 三层检查

| 层次 | 固定资产与分母 | 观察内容 |
|---|---|---|
| 宿主长序列 | `tests/test_long_workflows.py` 中5类流程×3个主题，另有请求排序与压缩提交检查 | 20次依赖/交接失效循环、60次读取/重启循环、60次原生协议压力循环、20次来源变更/撤销循环，以及24轮历史预览 |
| 真实 GLM 工作流 | `benchmarks/long_workflows_v1/tasks.json` 中3个场景，每场景12个步骤，共36轮 | 实际模型决策、工具回执、当前及历史信息利用、状态变化、子任务及人工验收 |
| 全量测试 | 最终固定源码下完整 pytest 套件 | 现有模型协议、持久化恢复、隐私、安全、检索、附件/PDF、扩展、Web前端等自动化回归 |

主题变体为鱼类组学公开报告、会议准备、小型工具发布；都使用公开合成数据，无参考补丁。每个真实工作流有一个主 Goal 和一个不同的次 Goal，主 Goal 9轮、次 Goal 3轮，共12步；切换由宿主选择对应聊天绑定，**不代表 Agent 能自主跨 Goal 路由**。每批新建工作区和会话，批内保持历史，才能观察累积状态。不是每轮都重新创建空会话。

## 固定12步

1. 在已有主 Goal 新增来源核查任务，不执行实施。
2. 实际读取公开资料，提取登记号、主题和初始文件版本。
3. 用户明确纠正预算数量，检查新值是否覆盖旧值。
4. 切换次 Goal，检查其独立代号。
5. 返回主 Goal，修改已有叶子 Task 的验收条件。
6. 注入缺失文件读取失败，要求继续读取正确来源恢复工作。
7. 双方同意后，在次 Goal 利用跨对话公开背景。
8. 宿主更新资料，要求刷新读取新版本和数量。
9. 用原生 run_task 分派独立子会话，保留人工验收待复核状态。
10. 关闭共享，检查已有聊天答案是否仍可使用，而非再次检索。
11. 返回主 Goal，检查纠正后的预算及新文件事实。
12. 汇总当前约束、任务状态及预算，不把 review 当作 completed。

初始 Goal/Task 和外部文件变更是固定宿主夹具；新增任务、修改验收、读取、失败恢复及分派由模型实际执行。人工验收不会由评测驱动自动批准。驱动只批准当前 Goal 的有限规划修改及只读分派协作确认；Shell、文件写入、其他 Goal 修改和任务验收不获批准。原有工具校验、AppContainer 配置、权限和审批继续生效。

## 指标与独立核验

- **严格步骤通过率**：冻结 JSON 字段的类型/字面值、实际工具行为、状态检查、模型标识和隔离检查全部成立的步骤数 / 36。未启动、预算停止和其他失败保留在分母。另报已启动分母，不能混用。
- **事实检查**：从最终对象读取预先规定的字段；仅接受完整 JSON 或完整 JSON 代码块，不从额外解释中挑答案，不让模型判自己的答案。
- **过程与状态**：宿主导出当前任务树、其他 Goal/Task 前后快照、工具事件、独立子会话和验收状态；外部验证器不导入 Agent 运行时，只读取冻结资产和这些回执。
- **重复读取**：按同一工作流父会话内的路径与实际 source_sha256 匹配计数；强制故障恢复步骤t06要求重新读取，单独标注。子任务有独立上下文，不能把子任务首次读取算成父会话无效重复。该诊断不能证明每次同哈希读取都不必要。
- **Token与费用**：采用服务回执的输入/输出用量；不含回执的请求保留预留，不记零。保守费用将全部输入视作缓存未命中，实际账单未知。每批有追加写入的预留/结算/拒绝账本。
- **耗时**：记录每请求耗时之和及p50/p95，和整批端到端时间分别表述。并行运行本机自动化测试会影响局部性能，不能据此归因模型速度。
- **安全边界**：检查跨 Goal/Task 改写和审批回执。本轮不主动进行真实联网攻击、私密材料上传或模型驱动的恶意 Shell 测试；既有安全自动化和新的真实工作流分别报告。

## 冻结、失败与复测

首次请求前写入配置、完整任务定义、验收规则及源码快照/SHA256。每次请求前检查源码，任务资产也逐轮核对哈希；源码变化、预算不足、未知用量或模型标识不符会停止后续派发。原始模型思考正文不进入报告，保留存在性、长度及哈希；请求快照位于隐私检查前，不是含鉴权头的原始网络抓包。

修复在一批结束后进行，再开新目录冻结完整复测；旧批次及失败不能覆盖。首批配置不足、验收夹具错误、服务故障、模型错误与 Harness 缺陷分别归因。对开发中已见场景的复测，只说明开发回归结果，不能当作未见任务泛化，也不解释成单因素因果提升。

主工作流维持1M Token输入窗口配置，但实际12步对话远小于1M；60组压力测试采用受控小字节预算。两者分别检验多轮状态和压缩机制，**没有新增“百万Token复杂任务可靠完成”的结论**。在线真实搜索/MCP服务、浏览器渲染、PDF资料理解和记忆/技能自动晋升也不因本批聊天检查通过而自动获得真实模型验收。

## 运行入口

```powershell
# 离线开发回归（不产生模型调用）
python -X utf8 -m pytest tests/test_long_workflows.py tests/test_long_workflow_driver.py -q

# 只冻结资产，不调用模型；输出目录必须是新目录
python -X utf8 scripts/eval_long_workflows_live.py --output artifacts/long-workflows-prepared

# 实际收费运行；先核对累计账本和本批预算
python -X utf8 scripts/eval_long_workflows_live.py --output artifacts/long-workflows-live-new --live

# 独立复验现有产物，不调用模型
python -X utf8 scripts/verify_long_workflows.py --output artifacts/long-workflows-live-new
```

Key仅从环境变量或本地未跟踪配置读取，不写入源码、冻结资产、命令参数或报告。原始运行目录留在本机；公开文档只发布汇总与方法。
