# 长期目标可靠性：改进、失败诊断与真实模型专项

2026-11-11。本轮实现与验证围绕长期目标、上下文和记忆，不增加通用插件市场或扩大工具权限。代码修复及其他历史Benchmark保持原样。

## 已完成的工程改动

1. **目标契约与依赖一致性**：备注/改名不再旋转Task上下文；plan_tasks变更会正确失效下游草稿；有产出的节点不能被规划覆盖；归档/取消/阻塞前置使下游验收失效；实际启动和结束再次检查依赖，旧绑定不能继续。
2. **当前状态与历史信息分层**：当前Goal/Task/祖先契约及未完成前沿进入保护帧，包含依赖问题、恢复原因与证据引用；历史压缩按类型、相关性和时间选择完整协议组，并记录最终送达及省略情况。
3. **记忆选择与检索复用**：自动学习条目先做范围/新鲜度/授权过滤，再复用BM25排名；适用条件与记忆整体保留或整体省略。代码Embedding不自动授权远程上传私人记忆。
4. **检索计算与交互错误**：按内容哈希复用文件解析，仍逐次检查内容和权限；BM25文档词频只统计一次。未创建Goal前的plan_tasks在询问确认前拒绝。

详细机制与边界见[实现说明](long-goal-reliability.md)。新增测试验证依赖、环路事务、历史保留、跨Goal隔离、恢复、预算失败、证据末端裁剪、同尺寸文件变更及远程记忆上传拒绝等行为。

## 真实GLM专项的实验口径

冻结6个**自设计开发用例**，每例3种上下文呈现各1次，共18次独立、单请求会话。它们验证模型消费上下文后的结构化判断，**不包含自主工具调用，不是完整Agent执行成功率，不是18道任务，也不是留出集**。没有比较Codex、Claude Code或DSH产品。

资产：`benchmarks/goal_continuity_v1/tasks.json`与`protocol.json`，运行器`scripts/eval_goal_continuity.py`。首次真实请求前冻结任务、外部判定字段、运行器、Harness和旧压缩器SHA256；每次新工作区，金标不进入模型请求或工作区。按任务交错轮换呈现顺序，避免全部基线先跑。全部原始输入、结构化回答、用量、耗时及失败保留。

| 配置 | 固定值 |
|---|---|
| 服务/模型 | 智谱普通API，`https://open.bigmodel.cn/api/paas/v4`，`glm-5.3-flash` |
| 采样 | temperature=1，top_p=0.95，Thinking enabled，reasoning_effort=low |
| 限额 | 输入JSON保守字节预算16384，输出1024 Token，单请求90秒，并发1，传输尝试1 |
| 调用 | 共18次；已知Token上限200000并做请求前保守预留，未知用量停止后续派发 |
| 工具/费用 | 自主工具步数0，搜索0，Embedding0；真实扣费未知 |

字节预算不是模型真实Token窗口。普通会话使用冻结旧压缩器，后两组使用当时的新压缩器/任务树；因此呈现、结构和压缩策略同时不同，**不能视作任务树或记忆的单因素因果实验**。无关长文本由测试作者生成，结果只适用于这个人为压缩压力条件。

总已知用量 **63,829 Token**；18次均完整返回并可解析JSON，缺失用量为0。耗时仅指单次模型调用及客户端处理，不含准备工作区或人工审批等待；样本太小，不作稳定时延结论。这里没有Tool Calling，不能将完整JSON返回称作原生工具协议零错误。

## 失败定位与修复后边界

**早期证据：** 原实现先选中了相关read_file，但最后为满足预算按FIFO删除历史条目，又删除了最早的关键指针。请求准备审计证明该指针没有进入模型，所以三组回答unknown不应归因为模型忽略已提供证据。修复让最后裁剪继续遵守相关性，不将evidence_id等JSON键名计作相关性。

**状态解释：** 前置归档用例中，两种任务树呈现仍选择了下游“撰写报告”，没有选择先恢复“资料核读”；需求修订用例的一次输出也选错下一步。后续补充前沿的依赖问题、归档状态、恢复原因和可执行标记，并明确“可执行不是授权”。没有宣称这些提示已通过新的模型效果复测。

**离线修复复验：** 同一冻结任务/金标/运行器、同一输入预算，使用最终代码生成18份新上下文，不请求模型、不产生新通过率。在早期证据用例中，旧呈现仍不包含指针，两个新呈现实际包含关键指针；专项工程回归还确认接近预算上限时该指针被保留。该证据只证明输入可见性修复，不证明模型最终必然答对。

首次离线重放曾因新增状态字段使保护帧过大而明确失败；后续省略空字段并减少冗余说明后，固定预算重放完成。没有扩大输入预算、修改金标或隐藏该失败。最初无API的预检也曾暴露旧压缩器无法满足过小的设计预算，该问题在正式首次调用前处理；正式协议始终为16384字节。

**本轮没有第二批真实请求来替换以上失败。** 真实调用期间源文件保持冻结；正式批次后才修复continuity/native_context并增加工具前置校验。最终版本与真实批次版本有差异，最终版的模型效果仍待新的独立验证。

## 真实网页验收

独立8780工作区，实际浏览器输入鱼类汇报规划，确认规划方向，保存两项manual任务及显式依赖；随后通过聊天改名为“文献核读”并添加备注。核对任务ID、会话、规格版本、验收要求和下游依赖；不以模型自述替代数据库核对。

首次规划模型调用顺序错误：在create_goal前调用plan_tasks，导致确认后失败；模型随后创建目标并重试，最终保存成功，所有失败和确认保留。后续增加调用前校验，相关回归证明非法规划不再请求协作确认。这里不是隐藏失败后的完美演示。

首轮界面总耗时约594秒包含测试期间等待操作者确认，不能当作模型生成耗时。改名回复界面约20秒，也不是稳定延迟Benchmark。实际页面和日志位于本地证据目录；最终版是否重新启动、回归结果及版本核对另记录在检查汇总。
