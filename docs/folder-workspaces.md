# 文件夹工作区

左侧“工作区选择”→“＋ 打开文件夹…”支持系统目录对话框，也可粘贴已有文件夹的绝对路径。默认保存最多20个目录，不会创建、搬迁或删除用户文件夹。名称相同的文件夹可从选择框的路径提示区分。目录不可访问时显示错误，不另建同名空工作区。

每个目录有独立的`.pico`状态，包括目标树、会话、运行记录、附件和协作设置。目录列表保存在初始目录的`.pico/workspaces.sqlite3`，可用启动参数`--registry`指定其他登记文件。初始目录和登记文件应长期保留。子目录仍是独立工作区；文件夹隔离不是额外的OS安全沙箱，工具继续遵循现有路径与AppContainer策略。

选中的工作区ID保存在页面URL。API请求携带`X-GoalTree-Workspace`，图片预览携带同名查询参数；每个工作区的CSRF令牌分别验证。浏览器另一个标签页选择目录不会重定向本页的审批、附件或工具请求。切换中清空旧树和消息，并重新获取新目录状态；失败恢复原选择。新打开目录的`.env`不会覆盖宿主进程的模型配置。

当前运行、上传或设置保存期间不能切换目录；需要等待结束或先停止。同一Web服务只执行一个Agent，其他目录仍可浏览。系统目录对话框运行于本机，因此该服务适合本地使用，不是远程用户的文件上传功能。

## 规划的上下文与延迟

新目标的协调器只获取当前目录身份，具体文件由模型按用户需求读取；不会自动注入README、项目配置或Git历史。对于缺少主题的会议规划，应先澄清或明确标注暂定通用结构，不以目录中的旧项目猜测题材。已有Goal仍保留其明确绑定的上下文，执行子任务仍使用完整工作区能力。

智谱`glm-5.3-flash`网页协调器保留Thinking与原生Tool Calling，将`reasoning_effort`设为`low`；实现子任务维持`max`。服务端记录模型请求配置及流式阶段耗时，前端显示真实阶段与正文。低思考强度不保证服务商固定时延，也不取消规划方向、安全审批或验收要求。首个网络/分析事件、首个工具参数、完整模型结果、最终正文及含人工审批的整轮耗时是不同口径，应分别说明。

```powershell
python -X utf8 scripts/run_goaltree_glm.py --workspace <已有文件夹> --port 8773 --network-route direct
# 通用配置入口也支持目录选择：
python -X utf8 -m goaltree.web --cwd <已有文件夹> --harness-profile workbench --port 8765
```

凭据仅从宿主环境变量或被Git忽略的本地GLM配置读取。登记目录不会放宽工具权限。此轮浏览器验证包含粘贴目录、往返切换、刷新、真实规划与审批；系统目录对话框的调用与取消有自动化接线测试，未将其算作原生窗口人工操作验收。
