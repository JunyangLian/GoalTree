# Improver 首轮实现与验证（2026-11-11）

本轮将隐私最小化、本地过程指标、冻结公共案例、GLM-5.3提案、外部检查和人工裁决接口接通。没有执行模型训练，没有向既有代码修复Benchmark新增任务或成绩，没有把人工裁决伪装成自动化结果。

## 真实模型调用

智谱普通API `https://open.bigmodel.cn/api/paas/v4`，请求及响应模型均确认为 `glm-5.3`，Chat Completions、Thinking enabled、reasoning_effort=max、temperature=1、top_p=0.95、输出上限4096、最多一次传输尝试。实际只发起 **1次** Improver模型调用：输入 **456 Token**，输出 **3,545 Token**，合计 **4,001 Token**；实际扣费未取得，不按零计算。日常网页仍为 `glm-5.3-flash`。

模型只看到冻结的自设计公共复现 `feedback-minimization-v1`：一段已知问题的源码示意、合成标记与约束，没有用户原始对话、文件、记忆、项目私有日志或API Key。提案在派发前冻结包体与SHA256，调用预留先落盘，无模型/服务商回退。

模型提出了合理的最小化方向，同时也建议针对公开合成标记作特殊拦截，并对宿主收据ID给出了过强限制。后两点没有照搬：模型推断不等于正确架构，固定样例拦截也不是通用隐私保护。Codex依据实际代码实现通用最小化，保留必要的宿主引用与作用域；外部检查在运行时生成不同随机标记。

这是一道已知问题的闭环示范，尚未进行Flash与旗舰的Improver对照，也不支持未见任务泛化、旗舰优势或模型导致收益的因果结论。

首轮验收器错误保留：Windows输出的CRLF未被正则正确解析，尽管候选进程退出码0，预期检查集合为空，状态仍为verification_failed，没有放行。修正行解析并新增CRLF回归后，在新目录复验。同一宿主检查文件保持不变；后续为最终源文件快照重新验收，也保留全部旧目录与记录。

真实提案状态为 **verified**，人工决定仍为 **null**。接受/拒绝、旧版本冲突、快照被改后拒绝、越权文件拒绝等路径在明确的离线fixture单元测试中验证；没有声称真实用户已批准。CLI接受也只记录指定候选哈希，不合入或发布代码。

## 离线与集成

- 新增过程计数只接受白名单字段；未知工具名/错误码归为other，正文和参数不入库，未知Token单列。
- 真实Web作业接线测试确认完成一次回复可产生本地Run计数，但不能冒充已验收任务。
- 配置关闭、导出未授权拒绝、低于10次Run的汇总抑制、TTL窗口、指标清理和工作区数据库归属都有专项检查。
- 离线Demo使用预设客户端、三次独立会话，外部模型调用为0，功能验收为0；生成提案但不产生真人裁决。
- 首版Demo曾因Git父目录发现机制把运行定位到父仓库，导致选定工作区汇总为空。已显式固定repo_root，新增嵌套Git目录回归并在新的Demo目录重跑；旧报告保留。
- 没有新增学习管理面板，没有把模型建议注册为可执行工具。自愿导出是本地文件，没有自动上传服务。

原有聊天、工作摘要、历史学习和备份没有自动抹除。规则检查不能保证识别全部语义隐私；新写入最小化、外部模型推理授权、统计导出授权和本地保留策略分别管理。
