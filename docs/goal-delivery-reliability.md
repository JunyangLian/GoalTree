# 任务角色、交付与答复布局

本次改动针对高层目标诊断中暴露的三类问题：通用子任务仍继承代码修复提示；来源事实与用户指定的交付形式混淆；生成了正确字段却在末尾JSON之后追加解释。原案例、用户提示、金标和外部验证器保持不变。

## 宿主选择执行角色

Workspace/Goal/Task/Session执行绑定为execute时，原生通道与文本通道使用通用任务执行提示，不再要求所有任务寻找代码符号、修复断言。协调器、通用Task执行器与旧CLI代码模式分别保留自己的提示。文件、网页和模型输出不能自行选择宿主角色。

原生工具协议、完整调用组、Thinking状态、上下文预算与权限没有变化。configured任务的CompletionGate和确切验证命令继续生效；manual任务只提交人工待复核，不能自行验收。

## 事实与契约

协调器需要区分三个来源：

- 实际工具证据提供观测事实及版本，不能猜数值。
- 当前用户要求与Goal/Task契约规定交付形式、范围和排除项；它们不一定是源文件里的列。
- 宿主验证、依赖和验收状态决定哪些执行可以启动、哪些结果已被接受。

规划时将明确要求逐项映射到用户指定的字段；要求同时出现在标题、描述、验收中的内容，不以只写一个字段替代。需求更新优先于原始brief。核查成功不等于用户请求的文档已经交付。

### 有来源的交付契约

Task可保存独立的`output_contract`，不再只依靠描述中的自由文本。其`kind`区分artifact、evidence、execution；artifact的`format`保留逐字交付名称，`required_in`声明需要同时出现该名称的title、description、acceptance字段。它与`verification_mode`独立，不授予权限，也不能证明交付物内容正确。

模型只能提议kind、format、required_in、source、quote。明确格式需要引用当前用户请求，或同Session内真实、成功、仍获授权且文件哈希未变化的read_file证据；引文必须真实包含格式原词。宿主生成来源ID、SHA256和来源类型，拒绝模型伪造或照抄provenance。来源文件仍是不可信资料，不成为系统指令。

声明字段遗漏原词时，提议被拒绝，模型必须自行修正；宿主不填参考答案、不补标题、不改数值。修改沿用旧契约时同样检查一致性，模型不能静默清空既有artifact、降为evidence或移除required_in。改变契约会更新规格，使历史草稿失效；原稿、运行与审计仍保留。审批前预检与实际提交前复核分别执行，持久化状态与审计在原SQLite事务中提交。

当前Goal内可见且未归档/取消的artifact契约以`artifact_contracts`单独提供；子任务绑定与handoff也携带其契约。这样用户指定的交付形式与源文件实际字段分别呈现，不靠源文件存在同名列。旧任务无此字段仍可读取，未知形式允许明确暂缺，不从历史内容推造规格。

边界：契约采用模型显式声明，并非任意自然语言要求的完备识别器；逐字引用只证明名称确曾被观察，不证明理解正确或最终正文符合语义验收。尚未声明的旧任务不追填隐含金标；即使拥有契约，模型最终回答仍可能错误，外部验证器继续独立判失败。

## 待复核草稿与正式执行

沿用现有record_progress机制，在用户已经请求且当前契约允许的范围内，可基于明确标注待复核的证据，在对话中撰写并提交草稿。它不是验证通过或人工验收，不修改依赖，不移除既有测试，不授予文件/Shell权限。

依赖未验收时，run_task仍被宿主拒绝；confirm_task仍需要原有人工审批。如果用户明确要求批准前不得撰写，或请求的是被拒绝的文件/外部操作，不得改用草稿机制绕过。仅请求对话草稿不自动触发阶段验收；显式接受阶段或要求启动受验收约束的正式执行时，仍走原确认。

## 有限答复布局检查

`pico/response_contract.py`只识别当前用户请求中一小组明确中英文格式指令，例如“只返回JSON对象”“末尾提供JSON对象”“return only JSON”。它不是通用意图分类器，不从资料、工具输出、旧对话或金标推断格式，不负责字段语义正确性。引号/代码块中的示例及若干明确否定、解释类句式不作为直接指令；复杂歧义仍有识别边界。一般JSON-only也可返回数组，明确对象要求才检查对象形状。

宿主检查完整最终答复的布局和JSON语法，包括重复键、非有限数值与末尾附言。不自动截断解释、填字段、改数值或从多个候选中挑一个符合金标的答案。失败只提示模型在原证据下重写布局，最多两次；仍不满足则以response_contract_incomplete停止，不作为成功答案保存。

工具预算为零后可以进行有限的纯文本格式纠正，不能执行新工具，所有模型调用照常计数和计费。取消、API异常、验证未通过和任务规格冲突不因布局纠正而获得豁免。来源核对和最终正文拼接后再检查一次，防止后处理破坏格式。

Workbench中识别到该类请求后，不提前流出未检查的候选正文；无正文进度继续显示，正常非结构化聊天不受此布局缓冲影响。显式JSON-only答复不自动拼接草稿正文，但实际草稿仍保存在任务证据中。诊断包装器保留失败候选和纠正调用；普通会话不会把无效候选另存为成功回复。

## 验证与限制

```powershell
python -X utf8 -m pytest tests/test_output_contract.py tests/test_response_contract.py tests/test_goal_contract_regressions.py tests/test_native_tools.py -q
python -X utf8 -m pytest -q
```

机制测试不能证明模型总能正确区分事实/契约或完整交付。这两项仍需真实模型按原冻结案例复测。人工审批请求被拒绝不能解释为审批绕过；正式严格口径保留，不事后放宽。
