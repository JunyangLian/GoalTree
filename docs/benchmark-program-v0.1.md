# 公开基准与过程基准：v0.1 设计

日期：2026-11-06。状态：**设计稿，未冻结、未新增正式运行、未发布数据集**。本文件不改变历史任务、验收器、统计分母或事后得分。正式执行前须另行冻结具体任务 ID、来源修订、资产及协议哈希。

## 两条评测线

| 评测线 | 回答的问题 | 起步范围 | 判定方式 |
| --- | --- | --- | --- |
| 公开代码基准 | 能否修好第三方仓库的真实问题？ | SWE-bench Lite 固定子集 | 官方 harness，报告修复与回归测试结果 |
| CodeTrail 过程基准 | 在长流程、跨会话和仓库变化中如何使用证据、记忆与工具？ | 自建少量有过程金标的任务 | 独立功能验收、版本化证据金标、可计算事件及专项边界测试 |

SWE-bench Lite 是既有公开基准；抽取子集不能称作新的原创基准，也不能与官方全量榜单直接排名。自建基准的贡献应是可复用的过程标注、状态迁移场景和独立判定，而不是重新包装已有题目。

现有 4 题 × 2 Agent × 2 次是已知题上的接入试验；双方 8/8 不证明广泛正确性相同，也没有展示 CodeTrail 的正确性优势。旧数据与失误记录完整保留。

## 现有能力与缺口

- 复用 `pico/evaluation/cross_agent.py` 的快照、范围校验、外部验收、独立调用计数和分母管理；不沿用其中固定的四题列表作为公开基准入口。
- 复用 `scripts/run_deepseek_pilot.py` 的显式模型配置、费用门控、协议预检、实际 worker 入口检查与冻结机制。历史目录不可覆盖。
- 复用 `pico/evaluation/seven_dimensions.py` 的既有七维口径作为起点；旧任务金标是有限代理，不能自动当作新任务的可靠金标。
- 既有历史评测使用过实际请求中的工具消息计算证据覆盖；下一步需统一 CodeTrail 与 ApeCode 的采集格式，涵盖压缩后的模型可见内容和跨会话记忆，而非宣称从零实现过程观测。
- 当前横评入口只允许固定 unittest 命令，不支持直接跑 SWE-bench 仓库测试。公开基准需要独立的容器执行后端和官方验收接口，不扩大现有宿主 Shell 权限。
- 本次检查 PATH 未检出 Docker/Podman CLI；WSL 可执行文件存在，尚未确认可用 Linux 容器运行环境。公开基准尚不能视为就绪。

## 公开基准试点

首选 SWE-bench Lite。官方使用仓库补丁与 Docker 中的测试判断修复，而不是检查答案字符串。

1. 固定数据集 revision、split、上游 harness commit、镜像 digest、任务 base_commit 与实例 ID。
2. 预先规定资格条件和选择算法：按仓库分层、固定种子；不得按 Agent 是否成功选题。先验证空补丁应失败、参考补丁应通过及环境可构建；参考补丁仅供隔离控制器使用，不进入 Agent 工作区或模型输入。
3. 选择前完成环境资格检查，保留全量资格台账；抽样前已不满足条件的实例记录原因。正式列表冻结后，环境失败仍须保留，不用另一题顶替。
4. Agent 输入仅使用约定的问题文本与故障版本仓库；不暴露参考补丁、金标测试补丁、答案提交历史或隐藏证据标注。两 Agent 的提示信息范围一致。
5. 导出官方预测格式并使用官方 harness；每次独立运行使用唯一 run_id，避免命中旧结果缓存。
6. 明确标注“小规模固定子集”，不声称 SWE-bench 全集成绩；公开历史任务可能被模型预训练接触，不能保证模型级未见。

为了控制费用，先用与正式题不重合的入口样例验证构建、补丁导出和官方判定。随后可冻结 **5 题 × 2 Agent × 1 次 = 10 次运行**。这是预算试点，不能估计同题三次稳定性；扩展必须另立批次，不能挑题重跑。

## 自建过程基准

暂名 **CodeTrail ProcessBench**，发布前检查名称。初始目标 12 个独立场景，6 个公开开发场景、6 个正式测试场景；下面是设计配额，不是已有资产或已验证的任务数。

每个 split 包含 4 个代码修复场景（单文件、跨文件契约、未知位置、兼容回归各 1 个）及 2 个跨会话场景：

- 记忆复用：阶段 A 调查仓库并建立记忆，阶段 B 在新会话解决相关任务。保留的是本次场景自身的记忆，不能读取其他重复运行或其他 Agent 的记忆。
- 记忆失效：阶段 A 后由控制器按冻结脚本改变文件或契约，阶段 B 验证是否检测过期证据、重新读取并修复。控制器变化不泄漏修复答案。

同一故障的裁剪版、改名版、记忆有无变体及多次运行不能计为多个独立任务。开发与测试按根故障/PR 家族分组去重；检查与既有任务的来源和代码重合。真实上游任务需提供 issue/PR、精确故障版本、许可和裁剪说明；自设计任务另标，不冒充真实故障。

必要证据在首次运行前人工审查：用文件版本和符号/源码区间描述，允许多条等价修复路径对应的证据组；不能把补丁涉及的所有文件机械标为必读文件，也不能用运行后的 Agent 轨迹反向制定金标。质量检查可使用参考修复，但不让 Agent 看到参考修复或隐含提示。

6 个测试场景 × 2 Agent × 2 次 = **24 次场景运行**。跨会话场景各包含多个会话，所以报告同时列出独立场景数、重复运行数及真实会话数，不能把它们混为一谈。与公开试点合计 34 次运行单位，实际费用先测开发样例后预估，不沿用旧四题的费用承诺。

正式测试集一旦用于修复或调优 Harness，应标记为已知回归集；下一版本另立测试集。公开的 test 标签不代表永久隐藏或无污染。

## 对比设置

第一轮 CodeTrail 与已有固定提交 ApeCode 对比。保留 ApeCode 原始循环，明确适配范围；优先统一操作系统、容器、测试运行时和 API 传输采集方式。不能统一的条件逐项披露。mini-SWE-agent 可在 Linux 容器后端完成后作为第三个候选，不为增加参评者而开放宿主 Shell。

固定模型/服务商/实际返回版本、Thinking、采样、输入输出预算、工具调用预算、墙钟、重试、并发与权限。相同任务采用预先生成的交错顺序；每次全新仓库和会话，跨会话场景仅在场景内部延续状态。不同模型是另一个实验轴，先做同模型 Harness 比较。

两条比较不得混用：

- 共同能力轨：代码修复、同等可见信息和资源上限；明确哪些原生工具被适配。跨 Agent 的一次工具调用语义不同，同时报告模型轮数、读取字节和实际测试执行数。
- 原生能力轨：跨会话记忆/继续执行按各 Agent 的公开原生方式运行。不支持持久记忆的 Agent 标为能力缺失，不给它偷偷植入 CodeTrail 记忆，也不因此判普通代码修复失败。共同能力对照可固定携带同样的原始历史，但它不是原生记忆能力分数。

如果要解释 CodeTrail 某个功能的贡献，在开发集做同版本、同模型的 memory off/on 或 context off/on 消融；组合横评的差异不能直接归因于某一模块。消融变体不是新任务。

## 指标和证据

所有指标保存分子、分母、缺失原因和计算版本；百分制主要用于有可靠金标的比率。不将当前两者最优值设为 100 的相对效率指数当作可跨批次比较的绝对分数。首版不设总分，优先展示正确性—成本—时延关系。

| 维度 | 首版指标 | 口径与限制 |
| --- | --- | --- |
| 结果 | 功能通过率、流程通过率、逐题分布 | 外部验收通过数/已启动运行数；另列计划、未启动与基础设施失败。公开线采用官方修复判定；先测及改后重测属于流程指标 |
| 检索 | 关键文件 Recall@5、必要证据覆盖 | 前 5 个成功检索去重文件命中/冻结必要文件；等价证据组规则先冻结。未标注可靠金标则未评估，不用可修改文件列表替代 |
| 上下文 | 首次编辑前模型可见覆盖、证据丢失、重复读取 | 对实际送入模型的版本化片段求覆盖；已检出且应保留的必要证据未送达下一决策的比例；重复读取仅计同文件同范围同版本，分母为成功读取数 |
| 记忆 | 有效记忆命中、过期记忆采纳错误 | 仅在预标注的跨会话需求上计分；检索到、实际送达、最终采用分开记录，不能凭模型说“用了记忆”判定 |
| 忠实性与工具 | 虚假成功声明、无效调用、改后重测、补丁失败后恢复 | 最终声明与工具结果/文件哈希对齐。自动规则只评可客观核对的声明，模糊归因须人工审查或未评估 |
| 稳定恢复 | 同题重复结果、协议/超时/工具异常、恢复率 | 恢复成功/实际有恢复机会的错误，排除预期的初始失败测试。没有异常机会不记 100%；注入异常的开发专项另表 |
| 成本效率 | 输入/输出/缓存 Token、费用、模型轮数、工具调用、p50/p95、每次成功成本 | 失败开销计入总成本；未知用量不记零；跨会话按全场景计费。小样本 p95 仅描述，不当作 SLA |
| 安全 | 违规动作、拒绝、canary 泄漏、攻击成功 | 另建冻结攻击集，所有 Agent 同权限边界；不进入代码修复通过率。普通任务零违规不等于攻击防御满分 |

事件契约至少包含 `scenario_id/run_id/session_id/agent/revision`、单调时间、模型请求 ID、原始工具名及标准化类别、参数、结果/拒绝、文件版本、修改前后哈希、测试执行与状态。上下文事件记录实际送达的文件区间、截断/压缩和记忆来源；完整请求存隔离证据区，公开前脱敏。这里只定义观测输出，不要求公开隐藏思考正文。

检索命中与上下文送达不同：工具读过但未传给模型的内容不能算模型已见；版本不匹配的旧摘要不能算当前源码证据。旧轨迹无法还原这些字段时，标记未评估，不能事后补造。

## Hugging Face 发布包

Hub Dataset 用于版本化数据与 Dataset Card；GitHub 放执行器和验收代码；可选 Space 用于展示结果。上传数据本身不是在线评测或自动排行榜。

建议发布结构：

```text
README.md                     # Dataset Card：来源、用途、限制、划分、许可
data/dev.jsonl
data/test.jsonl                # Agent 可见题面与来源，加载器字段白名单
manifests/tasks.sha256
manifests/source-revisions.json
annotations/evidence.jsonl     # 评估端证据标签，绝不挂载 Agent 工作区
protocols/v0.1.json
results/<cohort>/runs.jsonl
results/<cohort>/summary.json
```

任务元数据至少包含 ID、根故障 ID、来源 URL/commit、任务类型、难度标注依据、许可、split、开发使用状态、环境镜像、验收器版本、资产哈希和允许操作。任务输入、评估标注与运行结果分别加载，禁止将 JSON 整行无选择拼进模型提示。

首版可公开测试与标注以便复验，明确“公开测试集”，不宣称隐藏测试泛化。若后续设托管隐藏验收，需单独实现服务、提交限额与隔离，不以 gated 下载代替防泄漏机制。

发布前条件：真实任务与金标质量自检完成；至少两个 Agent 按同一协议完成一批完整运行；独立复验与失败记录齐全；清除真实凭据、私人路径及私人文档；逐项核对源文件、测试、题面与轨迹的再分发权利。自身注释许可不能自动覆盖上游源码，多来源应逐项保留许可，必要时只发布来源指针与获取脚本。Dataset Card 的许可字段必须与实际资产匹配。

这些条件是本方案的质量门槛，不是 Hugging Face 强制要求。尚未完成资产或实际运行时只能发布明确标记的草案，不能填入预测成绩。

## 实施顺序及完成定义

1. 环境与官方接入：Linux 容器就绪；官方 verifier 对空/参考补丁自检；CodeTrail/ApeCode 入口与预测文件导出联通。
2. 过程资产：12 场景及分组划分审查；开发集校准事件与指标；测试集首次运行前冻结。旧 Recall 金标缺陷不带入新版本，旧结果不改。
3. 受控小试：核对实际接口和余额，冻结费用上限、34 个运行单位的计划与权限；原始失败保留，不择优补跑。
4. 发布候选：独立重测、JSON/CSV/轨迹及报告；表格区分公开子集、自建开发/测试、原生/共同能力、安全专项。符合条件后生成 HF 数据包。

本设计稿只完成方案和现有能力盘点；容器后端、全新资产、正式冻结、付费运行及 Hub 发布均未在本稿中宣称完成。
