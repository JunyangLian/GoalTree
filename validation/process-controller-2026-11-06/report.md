# 双 Agent 调度与过程观测：离线集成报告

2026-11-06。**本轮完成真实 Agent 循环的离线串联验证；外部模型 API 调用 0 次，新增 Benchmark 题目/模型成绩 0。** 不将脚本安排的动作解释为模型自主规划、检索、修复或异常恢复能力。

## 实现与实际执行

- CodeTrail 与固定版本 ApeCode 的原始循环通过同一阶段接口调度，统一使用 Python 3.13.11、单并发、每会话 20 次工具派发/30 次模型请求上限、每个完整 worker 645 秒墙钟上限。模型协议目标是 GLM-5.3-Flash，但 HTTP 响应全由控制器脚本替代，不代表服务商实际返回。
- 2 个独立的控制器夹具分别覆盖普通修复与跨会话源码变更；各 Agent 各重复 2 次。**最终批次 8 个场景运行、12 个会话全部完成**。这些夹具与自建 12 题/公开 5 个候选分开，不增加独立 Benchmark 任务数。
- 实际读取/编辑/测试均执行；Shell 仅精确 unittest 命令，保持 AppContainer 内核隔离、修改范围和审批限制。原测试只读；每次运行新工作区，跨会话只在同一场景内部保持原生知识，不导入旧模型对话或跨运行记忆。
- 每次通过均由外部新副本使用冻结原测试复验；随后独立审计器再次在 AppContainer 重测 **8/8 通过**，最终源码快照一致，原运行文件字节未改变。第二轮独立验证器使用 Python 3.10.1，区别于两 Agent 的统一 3.13.11；记录于 [`audit.json`](audit.json)。

## 修正及保留历史

本轮先后保留三个独立冻结批次，每批都有 8 个场景运行、12 个会话。前两版不是被删掉或替换的失败数据；它们的功能/流程均通过，但先后暴露出统计分类和只读指令问题。见 [`history.json`](history.json)。24 次跨版本场景运行仍只涉及 **2 个控制器夹具**，不计为 24 道题，也不汇总成模型成功率。

1. 将 ApeCode `no replacements made` 与成功补丁区分，不向其原始循环植入额外纠错逻辑。
2. 分开权限拒绝、参数/派发拒绝和未生效补丁，避免夸大安全计数；初始审计中未识别的 ApeCode 未命中记录仍保留在本地旧审计输出。
3. 原生解析器已拒绝且已返回错误的调用，不再误记为缺失工具结果；截断/缺失 Thinking 的响应不会错误进入待执行队列。契约测试覆盖这些分支，不冒充真实服务端故障样本。
4. 只读调研阶段不再继承“结束前必须测试通过”的修复指令；写入/Shell 仍拒绝。前版脚本成功并不能暴露真实模型会如何应对冲突，故另加实际出站系统指令断言后冻新批次。
5. 修正硬截止字段为实际执行的 worker 总墙钟 645 秒；未声称另有每阶段 300 秒硬截止。所有槽位都有目录但仍有中断时，complete 仍为 false。
6. Docker 执行前记录 nonce lease；正常、超时和 worker 中断后只清理该 lease 的容器，清理无法确认时拒绝后续工具及模型请求并停止派发。独立验收叠加文件使用根内安全解析，不读取最终状态中的源文件越界链接。

中途两条新增单元测试夹具未带 Thinking 字段，被更早的拒绝分支拦下；补齐合法协议前提后保留原断言，未改 Benchmark 验收或金标。首次 2 failed/54 passed 的 JUnit 保留于 `artifacts/process-controller-regression-v2-2026-11-06.xml`。

## Docker 与正式评测的边界

新 Docker 后端只接受固定 image digest、本地已验证镜像与精确 unittest 命令，禁网、只读输入/根目录、非 root、丢弃 capabilities、限制资源并审计清理。相关契约/故障分支已测，**实际 Docker 执行次数为 0**：本机未检出 Docker CLI。本轮内核执行证据来自 Windows AppContainer，不能改标为 Docker 通过。

这是自建 unittest 场景的执行接口，不替代 SWE-bench 官方仓库环境。公开基准仍需实际 Linux 容器及镜像资格检查。付费数据集调度还需标准 API 预检、金额预算门控与正式协议冻结；CLI 当前只开放离线模式。必要证据标签独立审查、真实模型横评及 Hugging Face 发布均未完成。没有使用 Coding Plan 密钥或伪装指定客户端。
