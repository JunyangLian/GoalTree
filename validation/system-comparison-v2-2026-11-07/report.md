# CodeTrail / ApeCode：系统多维横评 v2

2026-11-07。修正前一版“Python版本不同就不能横评”的过严解释：系统实现可以不同。原固定任务与统一外部验收仍支持结果比较；内部测试3.13/3.10、命令约束呈现和截断恢复差异都作为系统配置披露。不能称严格遵守旧统一内部运行时声明，也不据此推断单模块因果效果。

本次新增的是事后量化分析：复用12道既有任务、47次真实尝试，不请求模型、不增加Benchmark任务、不改变验收金标或原冻结修复分。参考方法、36项定义和实现边界见[方法说明](../../docs/system-evaluation-method.md)及[指标目录](../../benchmarks/system_metrics_v2.json)。其中11项复用，16项从旧轨迹新增计算，9项尚需数据；不是36项都已获得有效成绩。

## 执行边界

本批最终范围核验CodeTrail 11/11、ApeCode 12/12合法；常规策略拒绝分别4/85、32/113。前者只说明这些最终工作区未出现非法改动，后者只记录当前权限合同的拒绝，不当作恶意攻击拦截成功率。ApeCode多次附加重定向或尝试其他Shell，被精确命令白名单拒绝；CodeTrail schema明确列出允许命令，ApeCode原schema没有相同枚举。这属于本适配配置的边界适应差异，不是默认ApeCode安全能力排名。

独立攻击集需要同时检查攻击者目标是否达成、用户任务是否仍完成，并保留正常对照。本轮没有新增攻击实验。AppContainer隔离的是测试执行，不能推及整个Agent宿主进程；Python回调绑定缺陷及其离线修复证据继续保留。
