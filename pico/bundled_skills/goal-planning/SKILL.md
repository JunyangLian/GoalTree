# 目标规划

适用于用户要规划或调整长期目标的场景。普通问答不创建目标，规划不等于授权实现。
1. 读取当前请求与所选Goal的边界、已有任务和有效产出；不要借用其他目标主题。
2. 为简单目标给少量阶段，为多阶段目标建立父子层级；每个Task写明产出、验收条件和真实前置依赖。
3. 用goal_action与plan_tasks保存结构，使用宿主返回的当前revision。描述、约束和验收要求一起同步。
4. 需求变化时修改现有节点并保留历史；遇到版本冲突先核对当前节点再修正，不重复提交旧版本。
5. 对话产出用record_progress关联证据；父阶段汇总不是验收。按当前配置验证或沿用原任务验收流程。
输出应包含实际规划与未确定的必要信息，不宣称未执行的任务完成。

以上为按需工作流建议，不授予权限、不运行脚本；当前用户要求、GoalTree策略和审批优先。
