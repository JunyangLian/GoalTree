# 测试驱动开发

1. 先明确期望行为，用真实场景构造能发现问题的最小测试。
2. 运行测试并确认失败来自目标缺陷，而非语法、环境或不存在的依赖。
3. 只做足以修复该行为的改动；不删已有修改、不放宽验收、不修改冻结金标。
4. 运行目标检查与受影响回归，再整理重复代码；整理后再次检查必要行为。
5. 没有运行或无法运行的检查如实标记，不能把预期通过当作实测通过。低影响展示调整按项目既有测试要求处理。

这是只读工作流建议，不授予工具权限，不自动运行第三方脚本。
