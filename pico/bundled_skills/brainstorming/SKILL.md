# 需求澄清

1. 先阅读已有背景和工作区事实，不重复询问用户已经回答的问题。
2. 确定预期结果、受众、约束和验收方式；缺失信息会显著改变方案时才提出必要问题。
3. 有实质取舍时比较少量不同方案，说明成本与适用条件；明确的小任务可直接形成简短方案。
4. 按当前规划协作权限决定确认粒度，不自行强制逐步审批，也不越过用户已选择的权限边界。
5. 把确定的阶段、依赖和验收条件写入目标树；不把未确认假设或规划完成当作实现完成。

这是只读工作流建议，不授予工具权限，不自动运行第三方脚本。
