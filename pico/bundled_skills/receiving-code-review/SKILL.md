# 处理审查反馈

1. 完整阅读反馈，区分明确缺陷、设计取舍与缺少证据的推断。
2. 对照实际源码、需求和运行证据复现问题；信息不足时只询问必要的澄清。
3. 反馈不适用于当前项目时说明理由与证据，不因审查者或模型身份盲目修改。
4. 按影响逐项实现最小修复，保持原安全和审批设置；每项修改关联相应回归结果。
5. 汇报实际解决项、未完成项与限制，不把接受建议等同于验证成功。

这是只读工作流建议，不授予工具权限，不自动运行第三方脚本。
